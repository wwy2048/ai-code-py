# 管理员治理以数据库角色为准

管理员身份每次请求都从数据库 `user.userRole` 读取，不使用前端声明或会话缓存。管理员端点统一经过 `AdminUser` 依赖；普通用户返回 `40101`。用户管理支持分页、详情、资料/角色更新和逻辑删除，响应模型不包含密码字段。App 管理可跨所有者分页、查看详情、更新名称/封面/优先级，并复用用户删除的数据库与产物清理流程。

## Status

Accepted（2026-10-31）。

## Consequences

- 修改用户角色后立即影响新请求的权限判断。
- 用户删除采用 `isDelete=1`，保留关联数据供审计；当前管理员不能删除自己。
- 精选列表只返回未删除且 `priority > 90` 的 App，并固定按优先级、更新时间倒序。
- 管理端删除 App 与用户删除调用同一个硬删除清理实现。
