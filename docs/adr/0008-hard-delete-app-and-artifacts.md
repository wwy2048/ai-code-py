# 用户删除应用时物理清除数据与产物

应用删除采用彻底清除，而不是软删除保留：同一数据库事务物理删除 `app` 和相关 `chat_history` 记录，事务提交后清理 Workspace、部署目录和 M2 记忆；COS 封面做 best-effort 删除。文件清理失败必须记录并告警，但应用不得继续可访问。

## Status

Accepted（2026-10-30）。

## Consequences

- 用户删除后不能恢复应用、对话或生成产物；不存在软删除恢复入口。
- 数据库删除与文件删除无法形成单一原子事务，需要明确“先提交数据库，再清理文件”的补偿顺序。
- 管理员审计不能依赖已删除的对话内容，只能保留独立的操作日志。
- 删除流程必须纳入 API 测试，覆盖越权、重复删除和文件清理失败。
